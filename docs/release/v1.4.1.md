# lsm-db v1.4.1 - Sidecars checked against their runs

bloom-lib 1.1 for the `bloom` feature, and bloom sidecars that are checked
against their run and rebuilt when they fail. Nothing changes without the
`bloom` feature.

## Changed

- bloom-lib 1.1 (was pinned at 1.0.0). It hashes little-endian with 64-bit
  lengths on every target, and its decoding validates. On x86_64 and other
  64-bit little-endian hosts its hashes and serialized bytes are those of 1.0,
  so every existing sidecar stays valid; the golden sidecar test confirms
  identical bytes. The requirement is `~1.1`, since bloom-lib promises fixed
  hashes and bytes for the rest of 1.x.

## Fixed

- A well-formed sidecar built over other keys made point reads miss keys the
  run holds. A sidecar bloom-lib 1.0 wrote on a 32-bit or big-endian host is
  one (its hashes differ), and so is one copied from another run. At open, a
  filter must now answer "maybe" for the last key of every block in its run's
  index; one that does not is dropped.
- A sidecar that failed its checks left its run without a filter until the
  run was compacted away. A dropped sidecar is now rebuilt from its run at
  open (one read of the run) and written again.

## Upgrading

`lsm-db = "1.4"`. Stores open as they are. A store whose sidecars were written
on a 32-bit or big-endian host has them rebuilt at its first open.

## Checked

The local gate on Windows and Linux (stable and Rust 1.85, every feature set),
CI on Linux, macOS, and Windows, and two new tests that fail on 1.4.0
(`tests/run_integrity.rs`: a sidecar built over other keys, and a rejected
sidecar).
