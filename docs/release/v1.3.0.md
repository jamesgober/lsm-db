# lsm-db v1.3.0 - Scans that seek

**A range scan costs its range, not its position in the key space.** Two new
calls, `close` and `scan_prefix`. The on-disk format and every checksum are
the same as 1.2.

## What changed

- **Scans seek to their start key.** Until 1.2 a scan filtered the whole
  memtable and read every run from its first block, so a scan near the end
  of the key space paid for every key before it. Now the memtable is read
  through `BTreeMap::range`, and each run starts at the first block whose
  last key reaches the start key, found in the block index. Results are the
  same: a new test checks 2,000 random ranges against a model, with every
  kind of bound including empty and inverted ranges, over five runs and the
  memtable.
- **`Lsm::close(self) -> Result<()>`** stops the compactor and flushes,
  returning the error that a drop (which flushes since 1.2.1) cannot report.
- **`Lsm::scan_prefix(prefix) -> Result<Scan>`** returns every key that starts
  with `prefix`. A prefix made only of `0xFF` bytes, or an empty one, scans to
  the end of the key space.
- New benchmark `scan_range`.

## Fixed (issue #3)

- **A failed flush kept nothing.** `flush` took the memtable before writing
  the run, so a write or sync error lost the buffered writes from the live
  handle. The memtable now stays until the manifest names the run; the
  flush returns its error and the next one tries again.
- **Directory syncs.** On Unix the directory is synced after a run and its
  sidecar are installed, after each manifest install, and after open removes
  orphans.
- **A missing manifest is refused.** A store writes its manifest when it is
  created; open refuses run files without one instead of deleting them. A
  checksummed manifest changes the format and waits for 2.0.

## Measured

Windows, x86_64, release. 1.2.1 and 1.3.0 alternated, three rounds:

| Benchmark (100 keys returned) | 1.2.1 | 1.3.0 |
|---|---|---|
| end of 100,000 keys in 8 runs | 42 to 70 ms | 0.30 to 0.56 ms |
| end of 50,000 keys in the memtable | 397 to 519 us | 18 to 44 us |
| start of 100,000 keys in 8 runs | 160 to 328 us | 154 to 468 us |

Point reads, writes, and the full scan are unchanged within noise.

## Upgrading

Nothing to do: `lsm-db = "1.3"`. The MSRV stays 1.85.
