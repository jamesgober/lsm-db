# lsm-db v1.4.0 - Opens that keep data

**An open no longer loses or overwrites data it cannot account for, and the
run footer, the write-ahead log, and the bloom sidecar are checked before they
are trusted.** Fixes from an independent review. The format version is
unchanged: 1.0 to 1.3 read the runs 1.4 writes, and 1.4 opens every existing
store.

## Fixed

- **One handle per directory.** Two handles on one directory handed out the
  same run names, and the second flush replaced the first handle's run: a
  flushed write was gone after a reopen. An open now holds an exclusive lock
  on a `LOCK` file until the handle is dropped; a second open, in this process
  or another, fails with `Error::Io` whose source kind is `WouldBlock`.
- **A directory without a manifest is a new store only when it is empty** (a
  lock file, temporary files, and a `wal.log` are allowed). Anything else is
  refused and left as it was; run files without a manifest are corruption, as
  in 1.3. Only a manifest that does not exist counts as missing.
- **`Lsm::rebuild_manifest(dir)`** writes a manifest again from the run files
  present, newest first by sequence number, after checking every run.
- **The footer's entry count is checked** against the run's blocks at open. A
  bit flip there used to pass every check, and with `bloom` the next
  compaction sized its filter from it and the process aborted on the
  allocation, at every restart. Runs written from now on also carry a footer
  checksum (below).
- **A build without `durability` refuses a non-empty `wal.log`.** It used to
  ignore the log, and the next durable open (Cargo features can change between
  builds without any code change) replayed old writes over newer data.
- **Damage in the middle of the write-ahead log fails the open** with
  `Error::Corruption` instead of cutting the log there and dropping every
  acknowledged write after it. A torn final record is still cut.
- **A failed background compaction is reported and cleans up.** Its files are
  removed on an error or a panic, the inputs stay live, and
  `Lsm::take_compaction_error()` returns the error. A panic no longer ends
  compaction for the handle's life.
- **A crafted bloom sidecar is checked, not trusted.** Its CRC32C detects
  damage only; a sidecar with a valid checksum over an unsound filter made a
  point read panic. The filter's shape is checked after decoding now.
- **A failed directory sync after a manifest install** removed the run the new
  manifest named, so a crash then left a store that would not open. The files
  stay now.
- Smaller fixes: a manifest naming a file outside the directory is
  corruption; a run file with the largest sequence number no longer
  overflows; a run's header magic is checked; overlapping blocks in a run are
  corruption, not keys out of order; with `durability`, a write over 64 MiB is
  logged instead of failing with an I/O error, and a log that cannot be
  removed at a flush is kept instead of leaving the handle without one.

## Changed

- **Footer check.** Runs written from now on have 12 more bytes, between the
  last data block and the index: `LSMFCK01` and the CRC32C of the footer. No
  data block covers them, so earlier releases read these runs; runs without the
  check still open, with their entry count checked against the blocks.
- **The block cache counts bytes.** Each block is charged the memory its
  decoded form holds; a block larger than a quarter of a cache shard (128 KiB
  at the default 8 MiB) is not cached. Before, the capacity counted 4 KiB
  slots, so blocks of large values held many times the configured memory.
- `wal-db` 1.4.
- **Docs say what compaction is.** It merges every run into one, so each
  compaction rewrites the whole store; the "leveled SSTables" in the
  description did not exist. Size-tiered and then leveled compaction are
  planned. The docs also say that a flush holds the engine lock, so reads wait
  for it, and that a scan holds its range in memory.

## Not in this release

- A flush still holds the engine lock while it writes its run, and a durable
  write holds it across its `fsync`. Moving the flush off the lock needs an
  immutable memtable and, with `durability`, a log sealed per memtable; it
  waits for a release of its own.
- Compaction still merges every run.
- The memtable's size still counts only key and value bytes.

## Upgrading

`lsm-db = "1.4"`; the MSRV stays 1.85. Code that opens one directory twice
now gets an error on the second open. A directory that holds other files and
no manifest is no longer taken for a new store. A build without `durability`
refuses a directory whose `wal.log` holds writes: open it once with the
feature to replay them.
